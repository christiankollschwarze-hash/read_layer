## HEUTE GEBAUT / GEAENDERT (liegt in pipeline/, lokal bereits ueberschrieben)
1. **stage_08b_wikidata.py** (NEU) — zweiphasige Wikidata-Anreicherung:
   - `--author <slug> --propose`: wbsearchentities -> Kandidaten + Lebensdaten zum
     Unterscheiden -> `authors/<slug>/wikidata_candidates.json`.
   - `--author <slug> --confirm <Q-ID>`: wbgetentities -> HART P569/P570 (Jahre),
     P19 (Geburtsort, Label aufgeloest), P800 (notable_works, Labels aufgeloest);
     WEICH Wikipedia-Sitelink -> quelle_weich; setzt verified=True; Index authors[slug]=Q-ID.
   - **wirkungssprache** abgeleitet: P103 (Muttersprache) bevorzugt, sonst erste P1412,
     dann via P218 -> ISO-Code (Q1860 -> 'en'). Wird nur gesetzt, wenn Feld leer
     (manuell Eingetragenes bleibt). Heuristik -> bei mehrsprachigen Autoren pruefen.
   - Mappt 1:1 auf das anlegen.py-author.json-Schema, kein neues Feld erfunden.
   - Pfad-Bootstrap: `_find_root` sucht aufwaerts den Ordner mit `config/` ->
     laeuft egal ob Datei in Wurzel oder in pipeline/, aus jedem CWD.
   - RUN_MODE=mock liefert feste Beispieldaten (Wikidata aus Container gesperrt).
2. **stage_09_blurb.py** (GEAENDERT) — autor-zentriert:
   - Loest Autor ueber Index auf (`author_of` -> author.json), uebergibt verifizierte
     `autor_fakten` (Lebensdaten, Geburtsort, notable_works) an die Blurb-Komposition.
     Prompt-Regel: bei verified=false / leeren Feldern knapp+neutral, NICHTS erfinden.
   - Schreibt `autor` (name_display) + `wirkungssprache` als Top-Level in stage09.json
     (zusaetzlich meta.autor fuer Rueckwaerts-Kompatibilitaet).
3. **stage_10_teaser.py** (GEAENDERT):
   - Zieht Autorname + `wirkungssprache` aus stage09.json (Top-Level, Fallback meta.autor
     bzw. config.SOURCE_LANGUAGE). Bleibt von genau EINER Datei (stage09.json) abhaengig.
   - Namensaussprache (Variante D) laeuft damit in der Wirkungssprache des Autors,
     pro Werk korrekt. Verifiziert: gleiche Sprache -> kein Hinweis; abweichend ->
     "pronounce it with <X> phonetics, naturally, without emphasis".
