## Header-Bug — an der Wurzel gefixt
**Symptom:** Kapitel-Header liefen zwischen Text und Audio auseinander
(`_00000_h`-Waisen, fehlende Header bei c001/c004, Index-Versatz c002).

**Ursache:** Doppelte, uneinige Quelle fuer den Header.
- Tagger (Stage 50) erzeugte h-Knoten LLM-abhaengig -> streute.
- 58b (LibriVox-Cutter) erfand einen eigenen kuenstlichen `_00000_h` aus
  meta.chapters -> zusaetzlich zum content-Header -> difflib-Chaos.

**Prinzip (bestaetigt):** Single Source of Truth = der getaggte Originaltext
(Stage 50). Alle nachgelagerten Stages ordnen sich unter; niemand erfindet Struktur.

**Fix (2 zusammengehoerige Eingriffe):**
1. **Stage 50** — Header wird deterministisch als erster Knoten `c<N>_00001_h`
   aus `chapter_title` (= ###CHAPTER###-Marke) gesetzt. LLM-h-Knoten werden
   verworfen. Prompt verbietet h-Tags zusaetzlich. Mock setzt keinen eigenen
   Header mehr.
2. **58b (stage_58_3rd_prty)** — kuenstliche Header-Zeile entfernt; Header kommt
   jetzt aus dem content (wird als normaler audio-tragender Tag mitgeschnitten).
   58b = reiner Ausrichter, kein Mit-Erzeuger.

**Ergebnis nach Neulauf:** alle 7 Kapitel `_00001_h` mit DE, 0 Orphans, 0 Saetze
ohne DE. Header-WAVs c001–c006 sauber auf `_00001`; c007-Header geflaggt
(Alignment unter Schwelle, Text vorhanden).
